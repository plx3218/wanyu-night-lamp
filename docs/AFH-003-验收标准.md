# AFH-003 App 使用情况监测：P0 验收标准

## 目标

在 Android 真机上验证“睡前计划 → 使用情况监测 → 连续 20 分钟提醒 → 用户选择 → 今晚记录”的最小闭环。首轮只承诺 Android，首台设备为 Xiaomi 15；其他 Android 机型需要单独记录验证结果。

## 口径

- 监测目标时间：当天最后一次生成的睡前计划；如果当天没有计划，则使用建档默认入睡时间。
- 监测开始时间：目标入睡时间前 2 小时。
- 计划锁定：监测已经开始后，当天新生成的计划不改变本次监测；次日再生效。
- 连续使用阈值：同一受管控类别累计连续使用 20 分钟。
- 同类 App 切换：不清零连续计时。
- 离开受管控类别超过 60 秒：重新开始连续计时。
- 白名单：不触发娱乐类提醒，也不被错误计入娱乐类连续使用。
- 手机停止使用：只能记录为“无手机使用代理指标”，不能表述为真实入睡时间。

## 验收场景

| 编号 | 场景 | 通过标准 |
|---|---|---|
| A1 | 使用情况访问权限已授予 | 能读取带开始/结束时间的前台片段，并显示最近采样时间 |
| A2 | 权限未授予或被撤销 | 明确显示 `usage_access_required`/降级状态，不把空数组解释成“没有使用” |
| A3 | 当天有多个计划 | 使用当天最后一次计划；监测锁定后新计划不改写本次窗口 |
| A4 | 当天没有计划 | 使用建档默认入睡时间，仍能生成监测窗口 |
| A5 | 同类 App 切换 | 类别内切换不清零，连续达到 20 分钟只触发一次提醒 |
| A6 | 跨类别切换 | 离开受管控类别超过 60 秒后重新计时 |
| A7 | 窗口外使用 | 不计入当晚监测、不触发本轮提醒 |
| A8 | 连续达到阈值 | 进入一次提醒状态，不重复发送相同窗口通知 |
| A9 | 继续 | 延后 10 分钟，最多两次；第三次达到阈值后转入准备结束提示 |
| A10 | 替代 | 记录用户选择的替代活动，不依赖 deep link 或播放器才能完成闭环 |
| A11 | 准备入睡 | 结束当晚监测并保存今晚记录；硬件灯离线不阻断通知和记录 |
| A12 | 基线期 | 只记录数据，不发送主动提醒 |
| A13 | 干预期 | 记录提醒次数、继续次数、替代选择和准备入睡动作 |
| A14 | 本地数据边界 | 原始包名、事件明细和浏览内容只保存在手机；服务器仅接收用户同意后的每日汇总 |
| A15 | 冷启动/重启/锁屏 | 恢复监测状态或明确展示监测中断，不伪造正常监测结果 |

## 真实用户试验口径

- 先进行 1 名内部用户的 3 天基线 + 7 天干预，再扩展到 10 名 Android 用户。
- 基线期和干预期都记录睡前娱乐总时长；核心指标为干预期相对基线期的减少百分比。
- 测试开始前说明使用情况访问权限、数据用途和本地优先存储策略，并取得同意。

## 不在本验收范围

- 不声称识别真实入睡时刻。
- 不承诺覆盖所有 Android/HyperOS 机型。
- 不把代码提交本身标记为需求池“已完成”；只有验收证据齐全后才更新需求池。
