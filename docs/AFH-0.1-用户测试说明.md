# AFH-0.1 用户测试说明

## 测试目标

验证晚屿是否能让真实用户在睡前娱乐时长上产生可观察的减少，而不是只验证功能按钮能否点击。

目标用户：睡前经常刷短视频的大学生，以及刚工作、晚上有报复性刷手机行为的工作人员。测试设备要求为 Android，具体品牌和型号记录在每日表单中。

## 测试分期

1. 先由 1 名内部测试者完成 3 天基线期，再完成 7 天干预期。
2. 内部流程稳定后，再招募 10 名真实用户，每人持续 7 天干预。
3. 基线期选择“基线：只记录”，不发送基于使用时长的主动提醒；干预期切换到“干预：会提醒”。两次切换都要记录日期和操作者。

## 测试前说明与同意

向测试者说明：

- 需要开启 Android“使用情况访问”权限，才能按 App 使用时段判断连续娱乐使用。
- 原始 App 使用记录尽量只保存在手机；服务器只接收测试者明确同意后的每日汇总。
- 不上传实际浏览内容、页面内容或原始包名事件明细。
- 测试者可以随时关闭权限、退出测试或要求删除本机记录。

## 每日操作

1. 早上确认昨晚记录是否存在，不把缺失记录填写成 0 分钟。
2. 晚上确认当日目标入睡时间；当天与 AI 对话生成的最后一份计划优先。
3. 在计划开始前确认权限中心显示正确状态。
4. 次日记录：睡前娱乐总时长、提醒次数、继续次数、替代活动选择、准备入睡时间和手机停止使用时间代理指标。
5. 记录异常：权限撤销、通知未到、App 被系统清理、手机重启、无网络、计划降级。

## 主要指标

- 首要指标：干预期平均睡前娱乐时长相对基线期平均值的减少百分比。
- 次要指标：提醒响应分布、继续次数、替代活动选择、是否愿意继续使用。
- “手机停止使用时间”只作为代理指标，不能写成“真实睡眠时间”。

## 证据要求

每名测试者至少保存：设备型号、Android 版本、权限状态、每日汇总截图或导出、异常说明和退出访谈回答。需求池的“已完成”只在整块 P0 功能联调和真实验收通过后更新。
